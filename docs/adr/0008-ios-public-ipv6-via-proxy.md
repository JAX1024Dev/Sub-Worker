# ADR-0008：iOS 公网 IPv6 经代理

- 状态：已接受
- 日期：2026-09-13

## 背景

iOS 官方客户端的 Packet Tunnel 可能收到应用预解析、缓存或直接使用的公网 IPv6
目标。这类连接不会经过 DNS AAAA 拒绝策略。实机日志确认，中国域名的 IPv6 连接
会先匹配 `geosite-cn` 并进入 direct，随后因 direct 没有可用 IPv6 路由而失败。

## 决策

- 仅在 iOS 配置中增加公网 IPv6 保护规则。
- 规则位于私网直连之后、中国域名直连之前。
- 私网 IPv6 保持 direct，其他 IPv6 目标使用 proxy。
- 保留 ADR-0007 的 AAAA 拒绝和 `ipv4_only`，减少应用优先选择 IPv6 的机会。
- 详细顺序和生成契约以 [RULES.md](../RULES.md) 为准。

## 后果

- 应用提供的 IPv6 字面量不再进入不可用的 iOS direct IPv6 出口。
- 国内公网 IPv6 流量可能经代理，延迟和代理流量会增加。
- 代理服务器必须具备可用的 IPv6 出口；IPv4 流量仍按原规则分流。
- macOS、Android、Windows 和 Linux 配置不受影响。

## 验证

- 生产接口生成的 iOS 配置通过 sing-box 1.14.0 检查。
- 2026-09-13 在官方 iOS 客户端完成实机验收，原问题网络环境下工作正常。

## 被否决方案

- 仅拒绝 AAAA：无法覆盖应用预解析、缓存和 IPv6 字面量。
- 拒绝所有 IPv6 连接：应用未必可靠回退到 IPv4。
- 所有平台强制公网 IPv6 代理：无实机证据支持扩大影响范围。
